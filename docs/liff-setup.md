（`LIFF_SHARE_ID` が仮置きのあいだは `liffShareReady()` が false を返して隠れます）。

## なぜこれが必要か

予定表のリンクは、予定の中身をすべて URL の中に抱えています（12件の月で 683文字、20件で 850文字）。
サーバーを持たない設計の代償です。

LINE の通常のトークメッセージは、**「表示する文字」と「飛び先」を分けられません。**
URL をリンクにしているのは LINE ではなく OS 側で、LINE 公式 FAQ にもそう書かれています。
だから「予定を見る」という短いラベルにすることが原理的にできず、トーク画面が URL で埋まります。

`liff.shareTargetPicker()` を使うと、**ボタンに URL を仕込んだカードを本人の名前で送れます。**
URL は1文字も表示されません。LINE公式アカウントは不要です。

## 作業の前に知っておくこと

- **必ず LINE の中で開かせます。** LINE 公式は「外部ブラウザでピッカーを表示するには
  SSO のログインセッションが必要。自動ログインでは発行されず、メールアドレスの
  ログイン画面が出ることがある」と明記しています。LINE の中（LIFFブラウザ）なら
  すでにログイン済みなので、何も聞かれません。
- **アプリが LINE のアクセストークンとユーザーIDを受け取る立場になります。**
  今は共有シートに文字を渡すだけで、LINE の ID を一切受け取っていません。
  ここが変わるので、**ストアの「データ安全性」の申告を書き換えます**（§5）。
- 必要な LINE アプリのバージョンは **10.3.0 以降**。1回の送信で最大5通まで。
- ボタンに入れる URL の長さ上限は **10,000文字**（2026年10月に 1,000 から引き上げ）。
  850文字でも余裕があります。

## 1. ページを公開する（私の作業）

LIFF のエンドポイント URL は、実際に開けるページでなければ動きません。

- ファイル： `share-liff.html`（リポジトリ直下）
- 公開先： `https://akihikoito-apps.github.io/judo/share-liff.html`
- GitHub Pages は `main` から配信されるので、**`main` に入れる必要があります**。

このページは、予定が渡されていないときは「予定が渡されていません」と出すだけです。

## 2. LINE Developers の設定（社長の作業）

<https://developers.line.biz/console/> を開きます。ログインは普段の LINE アカウントです。

### 2-1. プロバイダー

すでに公式アカウント用のプロバイダーがあれば、それを使って構いません。
無ければ「新規プロバイダー作成」。名前は道場名でも屋号でも構いません。

### 2-2. LINE ログインのチャネルを作る

公式アカウント（Messaging API）とは**別のチャネル**が必要です。

| 項目 | 入れる値 |
|---|---|
| チャネルの種類 | **LINEログイン** |
| チャネル名 | `My柔道 予定カード` |
| チャネル説明 | 道場の予定表をカードで送る |
| アプリタイプ | **ウェブアプリ** にチェック |

チャネル名に `LINE` という語を含めると弾かれることがあります。上の名前なら問題ありません。

### 2-3. LIFF アプリを追加する

作ったチャネルを開き、**「LIFF」タブ → 「追加」**。

| 項目 | 入れる値 |
|---|---|
| LIFFアプリ名 | `予定カード` |
| サイズ | **Full** |
| エンドポイントURL | `https://akihikoito-apps.github.io/judo/share-liff.html` |
| Scope | `profile` にチェック（最小限。これで足ります） |
| ボットリンク機能 | **On (Normal)** は不要。`Off` のまま |
| **シェアターゲットピッカー** | **オン** ← これが本体 |

### 2-4. 利用規約に同意する

同じ LIFF タブの中に、シェアターゲットピッカーの**利用規約への同意**があります。
**チャネルごとに同意が必要**で、ここを飛ばすと送信時に
`Need consent on shareTargetPicker usage on LINE developer site` というエラーになります。

### 2-5. LIFF ID を知らせる

LIFF アプリの一覧に出る **LIFF ID** を控えてください。
`1234567890-abcdefgh` のような形（数字10桁 + ハイフン + 英数字8桁）です。

## 4. 実機で確かめること（未確認の3点）

**ここが崩れると設計が変わります。**公開前に必ず実機で確かめます。

### 4-1. 予定データが `#` のまま届くか

いまアプリは `https://liff.line.me/{LIFF_ID}#u=...&t=...` という形で渡しています。
`#` 以降は**どのサーバーにも送られない**ので、LINE も GitHub も暗号文を受け取りません。

ただし LINE 公式の説明では、LIFF URL に付けた追加情報は `liff.state` という
**クエリにまとめ直される**とあります。そうなると暗号文が LINE と GitHub のログを通ります。
（中身は合言葉で包まれているので読めませんし、カードを送れば結局 LINE を通るので、
露出そのものは増えません。それでも、どちらなのかは把握しておきたい。）

確かめ方： `share-liff.html?debug=1` を付けて開くと、**「届いた経路」**が出ます。

- `hash` … `#` のまま届いた（いちばん望ましい）
- `liff.state` / `query` … クエリに変換された

### 4-2. アプリから LINE へ渡せるか

`isNativeApp()` のとき `location.href` で出しています。Capacitor は自分のホスト以外への
移動を横取りして OS に渡すので、OS が LINE を開く想定です（Android の WebView は
`window.open` が塞がれていることがあるため、この道を選びました）。

**ブラウザに落ちた場合も失敗で終わりません。**ページが `liff.isInClient()` で気づいて
「📲 LINEで開き直す」を出します。

### 4-3. 850文字の URL を仕込んだカードが、ちゃんと届いてアプリまで進むか

20件の月で試します。受け取り側は**1つも変えていない**ので、
公開中の選手アプリ 1.3 でも開けるはずですが、現物で確かめます。

## 6. 残っている設計上の割り切り

- **altText に URL を入れていません。** altText は通知とトーク一覧に出る文字なので、
  ここに URL を入れるとカードにした意味が消えます。代わりに
  `【錬誠館】2026年12月の予定表（12件）` のような読める文を入れています。
  その代償として、**Flex Message を表示できない古い LINE では予定を取り込めません**
  （Flex は 2018年の LINE 8.x から対応なので、実際にはほぼ全員が表示できます）。
- **カードに出る文字（道場名・月・件数・ひとこと）は暗号化されません。**
  LINE のメッセージ本文として送るので当然です。
  **会員のお名前はカードに入れていません**（URL の中だけで、合言葉で包まれています）。
- **「リンクで送る」「文字で送る」「QR」は1つも変えていません。**
  カードが使えない人も今までどおり送れます。
