### 上位5件の1：既存データを直すときの条件

計算式を直すだけでは、すでに保存された人の学年は変わらない。保存済みのデータを直す移行処理には、次の条件を付ける。手で学年を選んだ人は正しい値なので、誤って1年ずらさないことをいちばん大事にする。

**どこで値ができるか（コードで確かめた）**
- 自動：`refreshGrades()` が、区分が「未就学」・生年月日あり・`gradeBaseFY` が空・`gradeFixed` なしの人に、入学年度（`entryFYFromBirth`）が来たら `gradeBaseFY=入学年度`、`gradeBaseLevel=1` を入れる。`gradeTouchedFY` は書き換えない（index.html:14126-14129）。ずれているのはこの人たちだけ。
- 手入力：仲間の登録・編集で保存すると、`gradeBaseFY=その年度`、`gradeBaseLevel=選んだ学年`、`gradeTouchedFY=その年度` が必ず入る（index.html:14366-14374）。この値は正しいので直さない。

**直す人（すべて満たす人だけ）**
1. 生年月日（`birth`）がある。
2. `gradeFixed` がない（院生ではない）。
3. `gradeBaseLevel` が 1。
4. `gradeBaseFY` が、**今の生年月日から古い式で出した入学年度**（`afterApr2?y+6:y+5`）とちょうど同じ。
5. `gradeTouchedFY` が空、または `gradeBaseFY` より小さい（自動で小1にしたあと、一度も手で保存していない）。

**直さない人**
- 手で学年を選んで保存した人（`gradeTouchedFY` が `gradeBaseFY` と同じになる）。たまたま古い式の年度に小1で登録した人も、ここで外れる。
- 自動で小1になったあと、何かの項目を編集して保存した人。保存の時点で「画面に出ていた学年」が手入力として記録されるので、ずれたまま固まっている可能性がある。ただし、オーナーや保護者が学年を見て直してから保存した可能性もあるので、**自動では直さない**。代わりに「生年月日から考えると学年が1年違うかもしれない人」として一覧で知らせ、1人ずつ確かめてもらう（推測：この人数は少ないと見込む）。
- 生年月日をあとで変えた人（4 の条件に合わなくなる）、生年月日がない人、学年のない区分の人。
- 進級月が4月でない道場（自動の小1はもともと4月のときしか作られない）。この場合は移行を行わず、済みの印も付けない。

**直し方**
- 新しい入学年度（`afterApr2?y+7:y+6`、古い値より1年あと）を `gradeBaseFY` に入れる。`gradeBaseLevel` は 1 のまま。
- 新しい入学年度が今の年度より先になる人（2026年度なら、まだ未就学のはずの人）は、`gradeBaseFY`・`gradeBaseLevel`・`grade` を空に戻し、区分を「未就学」に戻す。入学年度になったら `refreshGrades()` が正しい式で小1にする。
- 直したあとに `refreshGrades()` を1回動かして、表示（`category`・`grade`）をそろえる。

**二重に直さない仕組み**
- 移行が終わったら、データ本体（`DB`）に済みの印（例：`DB.gradeEntryFix=1`）を入れて保存する。印があれば二度と動かない。端末ごとの印（localStorage の別キー）ではなく DB に入れるので、バックアップや同期で別の端末に移っても印がいっしょに移る。
- 印がない古いバックアップを読み込んだ場合は、読み込んだあとにもう一度移行が走るが、条件 4（古い式の年度と同じ）で選ぶので、直し済みの人（新しい式の年度）は選ばれない。
- 一度に全員を直してから保存する。途中で止まっても、直した人は条件 4 に合わなくなるので、次の起動で残りの人だけが直る。

**直す前の控え**
- 移行の前に、直す人の元の値（`id`・名前・`gradeBaseFY`・`gradeBaseLevel`・`category`・`grade`）を DB の中の控え（例：`DB.gradeEntryFixBackup`、日付つき）に入れて、移行と同じ保存で書く。DB に入れるので、書き出しのバックアップにも入る。
- 直す人が1人以上いたら、移行のあとで「◯人の学年を直しました（生年月日からの計算が1年早かったため）」と人の名前つきで知らせ、「元に戻す」で控えから戻せるようにする。戻したときも済みの印は残し、自動ではもう直さない。
- 0 人のときは控えも知らせも作らず、済みの印だけ付ける。

次に急ぐもの：E-1（iOS でシェアが黙って失敗する）、D-6（申込のメモだけの人が確認なしで消える）、E-10（購読が切れるとバックアップを取り出せない）、I-1（ロック画面が横向きで押せない）。

## 確かめて問題がなかったところ（参考）

- 容量オーバーで保存できないときは、赤い帯を出し続けてアラートで知らせる（index.html:7035-7063）。写真を足す前に容量も確かめる（7065）。
- 復元は形式を確かめ、失敗したら元に戻す。購読状態はこの端末の値を引き継ぐ（index.html:14818-14836）。
- アプリ版のバックアップは共有シートを使い、ダウンロードに落ちない（index.html:14733-14753）。
- 主な削除操作には確認がある（index.html:8163、8634、10328、10339）。デモのあいだは保存しない（7036）。
- iap.js とアプリ側の関数名（officeUnlocked・setPro・officeGateCheck・officePaySetChecking・refreshPaywallPrices）は一致している。二度押しも防いでいる（index.html:14879）。
- sw.js の VERSION と index.html の APP_VERSION は、どちらも v261 で揃っている（sw.js:5、index.html:5498）。
- 画面の日本語の多くは T() を通っていないが、画面全体を自動で訳す仕組みがあるので、決まった文は訳される（index.html:6872-6949）。
- ダークモード用の指定は無いが、色を固定しているので崩れない。
