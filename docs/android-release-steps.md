# Android 版の公開手順（2026-10-29 時点）

Google Play へ出すまでの段取り。**社長がやること**と**Claude がやること**を分けて書く。

---

## 前提：調べて分かったこと

- **申請に Android 実機は要らない。** Google 公式の「アカウント作成に必要な情報」に端末の記載はない。
- **組織アカウントなら「12人×14日のクローズドテスト」は免除される。** 公式の対象は
  「2023年11月13日以降に作成された**個人用**デベロッパーアカウント」。
  社長は D-U-N-S 番号をお持ちなので、組織アカウントで登録すればこの壁はない。
- **ビルドに Android Studio も実機も要らない。** GitHub の Linux 環境で AAB を作る仕組みが
  `android-prep` ブランチに入っており、2026-10-10 に両アプリとも成功済み（targetSdk 36）。

## 第1部：社長がやること

### 手順1　Play Console を開く

1. パソコンのブラウザで **play.google.com/console** を開く
2. アプリ用の Google アカウントでログイン
3. 「**デベロッパー アカウントを作成**」を押す

### 手順2　アカウントの種類を選ぶ

4. 「**組織**」を選ぶ（「自分用」ではない。ここを間違えると12人テストが必要になる）

> **ここが一番大事です。** 個人を選ぶと後から組織に変えられません。

### 手順3　組織の情報を入れる

5. **D-U-N-S 番号**：`700159705`
6. **組織名・住所**：D-U-N-S に登録されている内容と**一字一句そろえる**
   （ズレると審査で止まります。不安なら D&B の登録内容を先に見てください）
7. **組織の電話番号**
8. **組織のウェブサイト**：`https://akihikoito-apps.github.io/judo/`
9. **担当者名**・**連絡先メール**・**電話番号**
10. メールと電話にワンタイムパスワードが届くので入力

### 手順4　登録料を払う

11. **25ドル**（1回だけ。以後かかりません）をクレジットカードで支払う

### 手順5　本人確認

12. 政府発行の**写真付き身分証**（免許証・パスポート）をアップロード
13. 組織の確認は D-U-N-S で行われます

> ここまでで**数日〜30日**かかることがあります。D-U-N-S の情報が D&B 側で
> 最新になっていないと待たされるので、心配なら先に D&B で登録内容を確認してください。

### 手順6　終わったら Claude に伝える

14. アカウントが有効になったら教えてください。ここから先は技術側の作業です。

## 第2部：Claude がやること（アカウントができてから）

| | 作業 | 備考 |
|---|---|---|
| A | アプリの署名鍵（アップロード鍵）を作る | Play App Signing を使う。鍵は GitHub Secrets に入れ、公開リポジトリには絶対に置かない |
| B | ワークフローに署名の工程を足す | `ANDROID_KEYSTORE_B64` など4つのシークレット |
| C | Play Console にアプリを2つ作る | 事務・選手 |
| D | ストア掲載情報を整える | アイコン512px・機能グラフィック1024×500・スクリーンショット・説明文 |
| E | データセーフティ フォームを書く | RevenueCat へ送る情報を正直に申告 |
| F | コンテンツ レーティングのアンケート | 全年齢対象になる見込み |
| G | **課金まわりを Android 対応にする** | 下に詳述 |
| H | **プライバシーポリシー等を Android 対応にする** | 下に詳述 |

### G：課金まわり（ここが一番手がかかります）

いまのコードは **iPhone 専用の作りになっています。**

```
native/build-www.js
  office: { API_KEY: 'appl_...' }   ← Apple 用の鍵しかない
  player: { API_KEY: 'appl_...' }
```

必要な直し：

1. **RevenueCat に Google Play のアプリを登録**し、`goog_` で始まる鍵をもらう
2. `build-www.js` を**プラットフォーム別に鍵を出し分ける**ように直す
3. `storeKitVersion: 'STOREKIT_2'` は iPhone 専用の指定。Android では渡さない
4. **エラー文言が Apple 前提**になっている（`native/*/www/iap.js`）
   - 「App Store側で問題が起きています」
   - 「別のApple IDで使用中です」
   - 「設定の『スクリーンタイム』などの制限を」
   → Android では「Google Play」「Google アカウント」「ファミリーリンク」に置き換える必要あり
5. **Play Console に商品（定期購入）を作る**。ID は iOS と合わせる
6. RevenueCat と Play を**サービスアカウント鍵**でつなぐ

### H：プライバシーポリシー・利用規約・サポートページ

`privacy.html` `terms.html` `support.html` が **Apple 前提の文章**になっています。

> 「課金・サブスクリプションは Apple（App Store）を通じて行われ、決済情報は Apple が管理します」

Android から来た人がこれを読むと話が合いません。**「Apple（App Store）または Google（Google Play）」**
という書き方に直します。日本語・英語の両方にあります。

Play Console に出すプライバシーポリシーURL：
`https://akihikoito-apps.github.io/judo/privacy.html`
