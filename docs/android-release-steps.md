### スクリーンショットの落とし穴（調べて分かった）

Google Play は **「長辺を短辺の2倍以上にはできない」**。
iOS 用に作った 1290x2796 は比 **2.167** なので、**そのままでは出せない**。
moto g06 の実機スクショ（1640x720）も比 2.278 で同じく不可。
対処：拡大縮小はせず、**左右に余白を足して 1412x2796（比 1.980）** にした。
余白は元画像の端の列を伸ばしているので継ぎ目は見えない。
元の素材は iOS の画面写真ではなく**作り込んだ宣伝画像**なので、Android で使っても食い違いはない。

  選手側に無料お試しがあるかは要確認）

### C.　moto g06 で動作確認する（A のあと）

**Android 15 の実機で動かすのは、これが初めてになる。**

**moto g06 の OneDrive アプリからタップして入れる**だけ。
「提供元不明のアプリ」の許可を一度聞かれる。

### D.　（任意）Google Cloud でサービスアカウントを作っておく

RevenueCat と Play をつなぐ鍵で、**有効になるまで約36時間かかる**。
11月12日に作り始めると使えるのは14日ごろになる。先に作れれば2日早まる。

## 4. データセーフティ フォームの回答（案）

アプリが使っている外部 SDK は **Capacitor と RevenueCat だけ**。
解析も広告もクラッシュ収集も入っていない。
**端末の中にだけ置かれるデータは「収集」に当たらない**（Google の定義）ので、
名簿・出欠・月謝・写真・試合記録はすべて「収集しない」。

| 項目 | 回答 | 理由 |
|---|---|---|
| データを収集・共有するか | **はい**（1項目だけ） | RevenueCat が購入履歴を受け取るため |
| 金融情報 > **購入履歴** | **収集する** | RevenueCat の公式案内が「購入履歴の申告が必要」としている |
| ├ 目的 | アプリの機能（購入の復元・定期購入の管理） | |
| ├ 必須か任意か | **必須**（オフにできない） | |
| ├ 第三者と**共有**するか | **いいえ** | RevenueCat はサービス提供者であり、Google の定義では「共有」に当たらない |
| 個人情報・連絡先・位置情報・写真・音声・連絡先リスト | **収集しない** | 端末の外に出ない |
| アプリのアクティビティ・診断情報・端末 ID | **収集しない** | 解析 SDK を入れていない |
| 転送時に暗号化されるか | **はい** | HTTPS |
| 削除をリクエストできるか | **いいえ** | アカウントが無く、個人を特定できる情報を保持していない |

> RevenueCat は匿名の利用者 ID を使う。過去に「端末 ID」として差し戻された事例の報告が
> あるが、RevenueCat 側は「Google が匿名 ID を端末 ID として扱った例は見ていない」としており、
> 金融情報のみの申告で通った報告がある。**差し戻されたら端末 ID を足して出し直す。**

## 6. 定期購入の設計（案）

Play の定期購入は「定期購入 ID」＋「基本プラン」＋「特典（お試し）」の3段。

| | 事務 | 選手 |
|---|---|---|
| 定期購入 ID | `pro_annual` | `pro_annual` |
| 基本プラン ID | `annual` | `annual` |
| 更新 | 1年ごとの自動更新 | 1年ごとの自動更新 |
| 特典 | **1か月の無料お試し**（ストア文言と画像で約束しているので必須） | 要確認（iOS に合わせる） |
| 価格 | iOS と同じ（App Store Connect で確認して決める） | 同左 |
| RevenueCat の権利名 | `pro` | `pro` |

> Play の商品 ID は iOS と違っていてよい。RevenueCat 側で同じ Offering にぶら下げれば、
> アプリのコードは1文字も変えずに両ストアで動く（`native/build-www.js` が鍵だけ出し分ける）。

## 7. まだ分かっていないこと

**組織アカウントにしたら 12人×14日のクローズドテストは外れるのか。**

公式ヘルプ 14151465 は対象を
「2023年11月13日以降に作成された**個人用**のデベロッパー アカウント」としか書いておらず、
本文に「組織」という語が一度も出てこない。
作成時の種類で判定するのか、現在の種類で判定するのかが読み取れない。

**11月12日にアプリを作った瞬間、要件のカードが出るかどうかで分かる。**
出なければ外れている。出たらテスターを12人集める必要がある。

## 8. 済んでいる技術的な土台

- Android プロジェクト一式（`native/office/android` `native/player/android`）
- GitHub Actions での AAB・APK 自動ビルド（ubuntu-latest・Mac 不要）
- Capacitor 8.5.2 / compileSdk・targetSdk 36 / minSdk 24 / AGP 8.13 / Java 21
- 課金ブリッジの Android 対応（v307）：RevenueCat の鍵をストア別に、
  `storeKitVersion` は iPhone だけ、エラー文言と復元の文言もストア別
- `privacy.html` `terms.html` `support.html` の「課金は Apple」を
  「Apple（App Store）または Google（Google Play）」に修正（12か所・日英）
  ※この3枚は Pages で公開中なので `main` にはまだ入れていない。**公開日に一緒に入れる。**
- 予定表リンク `myjudo://` の Android 側の受け口
- `versionName` を iOS に合わせた（事務 1.3 / 選手 1.4）
